# 记忆注入实验：直接改 state.json 会怎样

> 日期：2026-10-25 ｜ 对象：v9.16 模块化实例（克隆自 `selfdrive_data/state.json`，round 3545）
> 方法：整树复制到 `runs/inject-20261025/`，只改副本的 state，不动仓库与线上
> 证据标签：`[实测]` 全部为本机复现 ｜ `[代码]` 行号可查

## 0. 一句话

**改 state.json 就是改它的记忆，而且立刻改行为**——不需要重训、不需要重启逻辑。
但它只对**三种记忆**里的两种有效：变换能改，事实不能改，概念只能慢慢并。

---

## 1. 实验 A：只改一个乘子，行为立刻变 `[实测]`

在副本里只塞一个键：`skill_multipliers = {"ask_brain": 0.05, "explore_file": 3.0}`，不碰任何代码。

| 动作 | 注入前 | 注入后 |
|---|---:|---:|
| ask_brain（提问） | **22.3%** | **1.6%** |
| explore_file（读资料） | 4.3% | **14.3%** |
| consolidate_memory | 26.1% | 29.6% |

（3000 次 `pick_action` 采样）

**结论：state 是它行为的总开关。** 想让它少问多做，改一个数字就行——这比改 prompt 可靠得多，也正是它相对 LLM 的真正优势。

---

## 2. 实验 B：注入一条"高置信的错误记忆" `[实测]`

现有记忆里已经有 `一加一→二`（support 18）和 `一加一加一→四`（support 1，错的）。再注入：

```json
"transforms": { "一加一→三": {"operands": ["一","一"], "result": "三", "support": 50} }
```

### 结果 1：它把错前提当公理用了

`transform_compose` 连续 5 次给出同一个推导：

```
三加五 = 六   （理由：三=一加一、五=一加四，合起来是 一加一加一加一加一加一）
```

推导结果"六"碰巧是对的（走了另一条链），但**理由是错的**——它用"一加一=三"展开了 3。
**这类错误最危险：答案对、依据错，外部看不出问题。**

### 结果 2：越确信的错误，越不会被检查

```
复检目标（recheck_transform）→ ('一加一加一', '四')     ← 只挑 support≤1 的
```

`TRANSFORM_RECHECK_SUPPORT = 1`（config.py:180）。所以：

- support=1 的错误会被复检、有机会被删；
- **support=50 的错误永远不会被问到**。

这是当前纠错机制的结构性盲区：**置信度越高，越免检。**

---

## 3. 实验 C：让大脑判假，它真的会删 `[实测]`

给 `一加一→三` 造一条推理记录，写一个 `[VERDICT:假]` 的回答，跑 `do_read_brain`：

```
判假前在表 = True
判假后还在 = False      ← 删掉了
剩余『一加一→X』： {'一加一→二': 18}
```

**变换类记忆的纠错闭环是通的**（v9.19 新加的逻辑，skills.py:527）。前提是它**被问到**——而"问不问"由上一节的复检阈值决定。

---

## 4. 实验 D：事实型矛盾，只能降权不能替换 `[实测]`

注入两条边：`小李|海边`（w=5）、`小王|海边`（w=5），然后让大脑回 `[VERDICT:假] 不是小李写的，是小王`。

```
小李|海边 = {'w': 3, ...}     ← 5 降到 3，边还在
小王|海边 = {'w': 5, ...}     ← 原样
冲突/修订类状态键 = []         ← 没有任何标记
mistakes 记录一条：{premises:[小李,海边], result:小王}
```

**它做不到"改写"，只能做"怀疑"**：

- 没有槽位（subject-predicate-object），所以无法把 `作者=小李` 换成 `作者=小王`；
- 只能把旧边的权重减 2，新事实和旧事实**并存**，谁权重高谁在推理里赢；
- 没有 `contested` 状态——它自己不知道"这里有两个互斥的说法"。

这就是"小李/小王"问题的机制级答案：**不是不肯改，是没有可改的结构。**

---

## 5. 三种记忆的可改写性（当前代码的真实能力）

| 记忆类型 | 存储 | 能否被更正 | 机制 |
|---|---|---|---|
| **变换**（一加一→二） | `transforms` | ✅ 能删 | `[VERDICT:假]` → 删除该键（skills.py:527） |
| **关系/事实**（小李—海边） | `relations` 无向边 | ⚠️ 只能降权 | 判假 → `w -= 2`，边保留 |
| **概念**（词汇） | `concepts` | ⚠️ 只能合并 | `merge_concepts` / 碎片归并 |
| **规则**（A∧B→C） | `rules` | ❌ 只会老化删除 | support/confidence + 超期清理 |

**缺失的那一格：命题。** 有命题才有"同一槽位的两个值"，才有 supersede。

---

## 6. 如果要把"改 state"当实验手段，怎么用

| 想验证 | 改哪个键 | 预期 |
|---|---|---|
| 它是不是真的"因为记忆而行动" | `skill_multipliers` 或 `emotions` | 动作分布立刻变（实验 A） |
| 错误信念会不会污染推理 | `transforms` 注入高 support 假式 | 会被当公理（实验 B） |
| 判假闭环通不通 | `infer_log` + outbox `[VERDICT:假]` | 变换被删（实验 C） |
| 事实能不能被改写 | `relations` 注入两条互斥边 | 只能降权（实验 D） |
| 重要性有没有被使用 | 任意 claim 加 `importance` 字段 | 代码里没有任何地方读它 |

### 注意事项

1. **改之前先备份**：`cp state.json state.json.bak.<时间>`，项目文化是只增不删。
2. **两个 state 别搞混**：线上是 `selfdrive_data/state.json`，根目录是旧快照。
3. **副本实验最安全**：整树复制后改副本，`BASE` 会跟着 `__file__` 走，天然隔离。
4. **别在跑着的时候改**：进程内 state 在内存里，下一轮 `save_state` 会覆盖你的修改。

---

## 7. 结论

- **能改**：行为（乘子/情绪）、变换（判假即删）。
- **不能改**：事实（只降权）、概念（只能并）、规则（只会老化）。
- **根因**：它有三种记忆（变换/关系/概念），**缺第四种：命题**。

下一步如果要让"小李→小王"成立，不是加一个 `importance` 分数，而是加一张 `claims` 表：

```
claim(subject=海边, rel=作者, object=小李, source=src_A, ts=..., conf=0.6, status=active)
claim(subject=海边, rel=作者, object=小王, source=src_C, ts=..., conf=0.7, status=active)
   ↑ 写入时发现同槽位不同值 → 两条都标 contested，旧值进 history
   ↑ 等验证（大脑 VERDICT / 多源一致）→ 胜者 supersede，败者 status=retired
```

这张表大约 200 行，接在 `learning.learn_from_text` 的写入口和 `skills.do_read_brain` 的 VERDICT 回写口上即可。
