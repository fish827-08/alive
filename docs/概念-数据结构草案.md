# 概念的数据结构：从"字符串"到"能用的东西"

> 2026-10-25 ｜ 目标：让概念既能被记住，也能被用来思考，还能被推翻

## 1. 现在的概念是什么

`concepts` 里只有 `{n: 出现次数, last: 最近轮次}`。
也就是说，一个概念 = **一个字符串 + 两个计数器**。
它没有"指什么"、没有"什么时候该用"、没有"怎么验证"。

所以它不是概念，是词频。

## 2. 提议的结构

```python
Concept = {
    "name": "加法",
    "type": "operation",            # object / operation / relation / state

    # 接地：它指向世界里的什么，以及怎么去看一眼
    "ground": {
        "world": "两堆物体的合并",
        "probe": "merge_and_count",  # 可执行探针：不知道就去数一遍
    },

    # 可用场景：什么时候该想到它（affordance）
    "affordances": [
        "两堆东西要合并",
        "我有 A，需要 B，问还差多少",
    ],

    # 可推导、可反驳的规则
    "rules": [{
        "text": "count(merge(A,B)) = add(count(A), count(B))",
        "confidence": 0.75,
        "support": 3,
        "source": "自己观察（2+3, 4+1, 5+2）",
    }],

    # 结构关系
    "links": {"inverse": ["减法"], "part_of": ["算术"], "contrast": ["分离"]},

    # 每次验证/被推翻的记录（append-only）
    "history": [],
}
```

关键不是字段多，是**多了三个原来没有的东西**：探针、可用场景、历史。

## 3. 思考时怎么用

```
情境输入
  → 匹配 affordances（哪些概念跟当前处境有关）
  → 激活最相关的概念（不是查表，是按处境点亮）
  → 调它的 probe 或 rule，得到可验证的结果
  → 结果拿去做决定（不是拿去答题）
  → 把"这次用对了没有"写回 confidence 和 history
```

注意最后一步：**使用本身也是学习。** 概念不是学完再用，是用着学着。

## 4. LLM 放在哪

| 让 LLM 做 | 不让 LLM 做 |
|---|---|
| 自然语言 → 候选结构（把"两堆合并"翻成 affordance） | 存概念（那是 KB/claims 的事） |
| 提出类比（"这跟上次那个情况像"） | 判真伪（probe 才判） |
| 提出新探针（"要不要换个数法试试"） | 当最终决策器 |
| 把推导讲成人话 | — |

一句话：**LLM 负责"说得像"，符号核负责"算得对"。**

## 5. 原型验证（`runs/concept_demo.py`）

```
阶段一：还不知道加法，只反复合并两堆再数
  观察：2+3 → 5；4+1 → 5；5+2 → 7
  → 提出不变式：count(merge(A,B)) = add(count(A), count(B))，置信度 0.30

阶段二：拿没见过的组合验证（先预测，再真去数）
  2+7：预测 9，实际 9 → 置信度 0.45
  6+3：预测 9，实际 9 → 置信度 0.60
  1+1：预测 2，实际 2 → 置信度 0.75

阶段三：不用真合并也能答
  17 + 15 = 32（依据是不变式，不是记忆）

阶段四：概念被用来做决定
  能量 3，这件事要花 5 → 缺 2 → 决定先休息

阶段五：被反驳
  1+1=3 → 假（按不变式应得 2）
  2+2=4 → 真
```

## 6. 与上一版的区别

上一版（Peano）：规则是我写死的，所以只是"会算"。
这一版：规则来自观察，并且必须经受住新例子的检验；概念还会被用在"要不要做"上。

**差别不在算法更复杂，在于概念的来源和用途变了。**

## 7. 诚实边界

- 假设空间是我给的（只给了"和"这一种候选）。所以是"在给定空间里发现规律"，不是"凭空形成概念"。
- 世界是我造的（两堆记号）。接地是接了，但接的是玩具世界。
- 离"真正理解"还差：自己提出候选不变式、自己选择探针、自己发现"该换个角度看"。

## 8. 接入辉月的最小步骤

1. 给 `concepts` 增加 `ground / affordances / rules / history` 字段（老数据自动补默认）。
2. 先只给两个概念接上探针：`加法`（merge_and_count）和 `能量`（读自身 energy）。
3. 在 `pick_action` 之前加一步"处境匹配"：能量不足时，优先激活"能量"概念，用它算缺口，再决定 rest 还是 explore。
4. 验收：不看它会不会算 17+15，看它在**没人叫它算**的时候，会不会主动算"我还差多少"。
