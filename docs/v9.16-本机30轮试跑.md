## 3. 六个观察

### 3.1 稳定性：0 异常 ✅

30 轮无一次崩溃，`main.run_round` 的异常处理也没被触发。对比 v9.15.2 一夜 37 次（`list.items` ×20、`rels` ×10、`re.Match` ×5、`NoneType` ×2），这次重构把稳定性做实了。

### 3.2 修剪在起作用，但方向有错 ⚠️

日记里出现了这条：

```
遗产碎片合并：『一加一』并入『一加一等』（剩余概念 269 个）
```

`sweep_legacy_fragments` 的规则是"短词是长词前缀 → 短词并入长词"。在没有 jieba 的环境里，长词往往是**句子碎片**，于是**真词被并进了碎片**。这一条比"碎片率 21%"更危险——它在主动破坏好概念。

同样的机制让抽象节点越聚越糊：

```
抽象节点生长：『个了』把 个了、料之间有什么、答案一样、联系了 打包成了一类
```

### 3.3 提问空转占 20% ⚠️

30 轮里 `ask_brain` 被选中 7 次，只有 1 次真的写出问题，6 次返回"提问节流中 / 本分钟已提问"。

原因在 `main.py`：

```python
idle = (action == "read_brain" and not ok) or (action == "ask_brain" and not ok)
if not idle:
    s["try"] += 1
```

空转不计入 `action_stats` → `pick_action` 的成功率学习永远看不到这次失败 → 权重降不下来 → 下一轮继续选它。**为了修 read_brain 空转，把 ask_brain 的学习也一起关掉了。**

### 3.4 老变换复检生效 ✅

```
[round 3564] ask_brain → 已向大脑提问 [Q-20261025-1148]
  （来自老变换复检（一加一加一→四））：
  我在复检一条很久以前记住的变换：『一加一加一等于四』——我当时不是很有把握。
```

v9.19 的 `recheck_transform` 真的工作了：它自己把那条错算式翻出来送审。这是这次试跑最有价值的一幕——**它开始怀疑自己过去记的东西了**（虽然只怀疑 support≤1 的）。

### 3.5 自言自语变成了可失败的下注 ✅

```
自言自语：下注《信息量》↔《重复推理》有关联（无边对，可失败预测）
预测落空：我赌《信息量》和《生物学名词》有关联，70 轮过去它们从未同现
```

从"预测共同邻居 → 必然命中"（旧版 30/30 命中）变成了"押一条不存在的边 → 可能落空 → 落空要复盘"。这是从同义反复到可证伪的一步。
