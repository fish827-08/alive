## 一、jieba 装好了，但结果有个反直觉的地方

**装在哪**：`D:/Project/alive/runs/venv/`（venv，未污染系统；`runs/` 已在 `.gitignore` 里）
**版本**：jieba 0.42.1 ｜ Python 3.13.14

### A/B：同样 6 篇资料，同样跑 3 遍

| | 不装 jieba（回退滑窗） | 装了 jieba |
|---|---|---|
| 概念数 | 92 | 84 |
| 概念样例 | `人工生命与涌` `研究如何在计` `算机中构建类` `似生命的系统` `经典工作包括` | `人工生命` `涌现` `宏观` `简单` `模式` `单个` `细胞` `结构` `ALife` |
| "碎片率" | **0%** | **1%** |

### 等一下——不装的时候碎片率是 0%，装了反而有碎片？

这就是这次实验最有价值的一条：**指标本身失效了。**

`碎片` 的定义是"短概念是长概念的子串"。滑窗切出来的是**等长 6 字块**，互不包含，所以检测器一个都抓不到——**它不是没有碎片，是碎片大到检测器认不出来**。装了 jieba 才出现真正的层级（`生命` ⊂ `人工生命`），碎片才第一次可见。

> 教训：指标定义依赖分词粒度。**用 A 指标去证明 A 修复有效，会自我循环。**

### jieba 也不是全好

```
"一加一等于二" → 一加 / 一 / 等于 / 二      ← 算式被切碎
"小李写的"     → 李写                        ← 人名/助词黏连
```

`_bump_transforms` 用的是原始正则，不受影响；但作为"概念"的 `一加一` 会变成 `一加`。所以换器官不是终点，**算式、专名还需要单独的识别规则**。

## 二、它现在会"怀疑"吗？

先定义：**怀疑 = 对同一个命题同时持有两个以上互斥候选，并给每个候选标置信度**。

按这个标准看它现有的四个机制：

| 机制 | 像怀疑的部分 | 缺的部分 |
|---|---|---|
| `edge_preds` 可失败预测 | 押一条边，60 轮后结算，落空要疼、要复盘 | 只是"猜错"，不是"两个候选打架" |
| `recheck_transform` 老变换复检 | 会主动把没把握的旧记忆翻出来问 | **只查 support ≤ 1**，越确信越免检 |
| `[VERDICT:假]` | 变换判假**直接删**；关系判假只降权 2 | 删了就没有"另一个候选"，是抹掉不是比较 |
| `mistakes` | 记住"这组前提被判假过" | 只避免重复，不产生替代解释 |

**结论：它有"赌注"和"复查"，没有"怀疑"这个状态。**

因为怀疑需要一个数据结构：同一槽位的多个值 + 各自置信度 + `contested` 标记。它的表里没有槽位（`transforms` 的 key 是"表达式→结果"，本身就是结果的一部分），所以两个候选只能作为两个不同的 key 并存——组合推导时 `direct[ops] = result` 后写覆盖先写，**它不比较，只覆盖**。

## 三、你的设想：把"训练数据"变成可实时更改的长期记忆

你的直觉有一半非常准，另一半需要拆开。

### 3.1 两种"改训练数据"，代价差 1000 倍

| 读法 | 做法 | 速度 | 可寻址 | 可回滚 | 副作用 |
|---|---|---|---|---|---|
| **A. 改权重** | 在线微调 / LoRA 热插拔 / 模型编辑（ROME、MEMIT） | 分钟~小时 | ❌ 改"小李"会动到它周围一切 | ❌ 只能再训一次 | 灾难性遗忘 |
| **B. 改外部记忆** | KB / claims 表 / 每轮注入上下文 | 毫秒 | ✅ 一行一条 | ✅ 删了就行 | 没有（但也不进本能） |

你要的"实时"，只有 B 做得到。A 的"实时"是营销词——一次 LoRA 训练最快也要几十秒到几分钟，而且你没法只改一个事实。

### 3.2 人脑其实是两套，不是一套

- **海马**：快、一次性、情景化（今天谁说了什么）——对应 KB / 情景记忆
- **皮层**：慢、统计、语义化（"小李这个人"）——对应权重
- **睡眠**：海马重放 → 皮层巩固。**这才是"记忆变成固有认知"的机制**

所以你说的"训练数据 = 固有认知"是对的，但中间少了一环：**巩固**。
没有巩固，"改训练数据"就永远只是"改笔记"，不会变成"本能"。

### 3.3 关键约束：可寻址性

问自己一个问题：**如果你能实时改权重，你怎么撤回一条改错的记忆？**

外部记忆删一行就完了；权重改错了，你只能再训一次，而且不知道有没有改坏别的地方。
**这就是为什么"需要被修改的东西"必须放外部，"不需要修改的东西"（语法、风格、常识）才留在权重里。**

### 3.4 三层记忆设计（可以直接接在现有代码上）

```
core_memory   （常驻）  每次 LLM 调用都带：我是谁、当前目标、最常用的 20 条 claim
claims        （检索）  按需查：subject-rel-object + source + ts + conf + status
kb / archive  （归档）  全量原文、旧对话、搜索结果
```

**晋升规则**（这是"训练数据"的可编辑版本）：

```
被检索次数 ≥ N 且 最近 M 轮用过  →  claim 晋升进 core_memory
连续 K 轮未被检索                →  降回 claims
被新证据 supersede               →  进 history（append-only），不再出现在 core
```

这样"固有认知"不是一块冻住的权重，而是一个**会自己浮上来、也会自己沉下去的记忆层**。LLM 每次只做推理，不持有记忆。

### 3.5 什么时候才真的该动权重

只有三类东西值得进权重：**风格、技能、反射**。
事实永远不要进权重——因为事实会变，而权重不会。

## 四、最小可做实验

1. 给现有 `concepts/relations` 加一个 `prominence` 分数（检索次数 × 最近使用衰减）。
2. 每轮把 top-20 写进 `core_memory`，随问题一起送给大脑（或未来的 LLM 模块）。
3. 观察 300 轮：`core_memory` 的内容会不会稳定下来？会不会被噪声顶掉？
4. 如果稳定 → 这就是"可编辑的固有认知"的雏形；如果不稳定 → 说明晋升规则还太糙。

---

## 五、一句话

**LLM 的权重是"天生不会改的部分"，外部记忆是"随时能改的部分"。你要的不是把后者变成前者，而是给后者一套"巩固与遗忘"的规则——那才是人脑真正在做的事。**
